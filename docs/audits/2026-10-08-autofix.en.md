# Audit and fixes — 8 October 2026

This pass reviews the code shipped after the [previous implementation](2026-10-07-implementation.en.md): library imports, concurrent changes and pack maintenance. General suites also cover scoring, finale, audio, access, recovery and persistence. No additional role bypass was demonstrated. This is a targeted local audit, not an exhaustive penetration test or another video analysis.

## Findings addressed

| Reference | Defect and impact | Fix and evidence |
|---|---|---|
| R01 | Valid ZIP headers with corrupt Deflate content caused an uncaught exception and a server error. | HTTP 400, unchanged metadata and released import worker slot. HTTP regression failed before the fix and passed afterwards. Host-only access remains enforced. |
| R02 | Activation and bulk updates omitted expected revisions, allowing another screen’s tags to be overwritten silently. | Each request carries a revision, advanced after each successful bulk save. The batch stops at the first conflict and retains progress and its explanation. Four FR/EN Chromium/WebKit scenarios simulate editing between requests. |
| R03 | Docker configuration generation and copying to a new pack did not explicitly apply Windows permissions; secrets could inherit additional readers from the parent directory. | Private directory before writing, private files after copying, repair existing configuration and reject links/junctions. Tests use an Everyone-readable parent. .NET applies permissions without changing the directory owner. If a legacy file allows reading/replacement but refuses ACL changes, an identical private copy replaces it atomically. Tested on Windows and encountered on the actual configuration. |
| R04 | Backup copied files during modification and could mix two state versions. | Graceful shutdown, stable copy, restart only services previously running, including after copy failure. Tested with a Docker function that never accesses the daemon. |
| R05 | Restoration merged directories, retaining newer files; Bridge identity/configuration was excluded. | Format-2 backup includes state, Bridge, volumes and images. Required files checked before stopping, complete state replacement and atomic Bridge configuration restoration. Simulated copy/install failures retain original data. Older incomplete backups require verified manual restoration. |
| R06 | Startup or restoration failure could leave a partially changed installation without automatic recovery. | Safety backup before mutation; attempt to recover prior data, Bridge, configuration and exact images. Explicit error identifies the backup if recovery also fails. Success/failure scenarios run in Windows PowerShell 5.1. |
| R07 | Reopening the library could show an old result fetched while the dialog was closed. | Refresh on opening. Tests wait for loading to finish before simulating concurrent changes, independent of browser speed. |

Maintenance backups exclude audio caches, music and the Caddy authority. FR/EN guides explain the short interruption, Backup before Stop, restoration confirmation and failure diagnosis. Maintenance paths containing commas are rejected before restoration because the Docker mount CLI treats them as separators.

## Local validation

- **1,157 Python tests passed**: 1,112 general tests, 44 FFmpeg tests with the subprocess PATH corrected, then one new legacy-file permission regression. Two Windows skips: POSIX permissions and unavailable symlink creation. Eleven separate integration tests are covered in CI.
- **52 Web tests passed**; build, TypeScript, Ruff, formatting, Pyright, Biome and protocol schema checks passed.
- **14 relevant browser scenarios passed** across the four FR/EN conflict cases and ten Chromium/WebKit pagination, editing and preview cases. Initial runs exposed a test setup race, removed by awaiting loading completion. Synthetic clips; no acoustic validation on physical phones.
- **14 maintenance/restoration regressions passed**: nine Windows cases and five exact replacement, failure and Bridge restoration cases. The Windows tests never access the Docker daemon and now also run in the Windows CI job. Included in the totals above.
- Protocol **10** and snapshot **8** retained. No data migration in this pass.

High findings have no listed fix in this database: 51 `wont-fix` and four `not-fixed` per Python image, eight `unknown` for Caddy. Two medium Python findings list Python 3.15/3.15 alpha fixes; this project validates Python 3.12–3.14 with an upper bound `<3.15`. A separately validated migration remains necessary. No FFmpeg/npm matches means no matches in this database for the declared components, not the absence of all vulnerabilities.

The native format-2 backup was executed and all its checksums verified. The corrected application is deployed on the LAN: app and Caddy healthy, Bridge online. Post-restart comparison preserves **two players, 12 archives and 68 tracks**, identities, answers, scores, metadata, cookies, shared access code, configuration and mounts. No tracks disappeared and no music files were changed. The certificate is unchanged; HTTPS was verified using the local authority. Windows refused the initial permission repairs; the corrected launcher subsequently starts normally and configuration bytes are preserved.

Private evidence: `.local/audit-20261008-image-scan/`, `.local/audit-20261008-python.log`, `.local/audit-20261008-ffmpeg.log`, browser results and `.local/audit-20261008-runtime-facts.json`.
