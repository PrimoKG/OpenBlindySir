# V0.2 implementation and compatibility

Historical V0.2 reference. Current V0.3 uses protocol **4** and snapshot **3**,
implements manual MC track choice, and adds Bridge distribution/diagnostics.
See the [current user guide](user-guide.en.md),
[Bridge installation](bridge-installation.en.md) and [operations](operations.en.md).

Protocol **3**, snapshot **2**, with migration from snapshot 1. Upgrade server,
Bridge and web UI together. Version mismatches are rejected explicitly. No
dependency or server FFmpeg requirement is added. The project remains a single
process with one active game, manually awarded points and private snapshots.

## Global scoring

Rounds close into REVIEW and keep answers. They can advance without scoring or
revealing tracks. The last close or an early ending enters FINAL_SCORE_REVIEW.
Only hosts receive review_rounds with played tracks, historical participants,
locked/captured answers, server reception timestamps and draft points. Ordinary
players and spectators receive no standings/other answers/metadata before final
publication. MC live answers are intentionally permitted, without points.

score_draft selects any played included round and replaces an integer ±1000;
explicit zero sets reviewed. final_set replaces a per-player correction. Drafts
do not append score events. final_validate confirms unchecked rows, appends all
non-zero round and final-adjustment events, then freezes and archives the game.
Legacy publish/undo_publish/adjust commands remain parseable and are always refused.

End-game is allowed in all phases and is a no-op once review/results is reached.
Before official audio start, cancel and exclude the unheard round. In OPEN,
close/capture and include it, or retain and exclude it in abandon mode. Played
cancelled rounds remain visible with included=false and zero points. No early
ending loses stored answers/drafts or bypasses final validation.

Snapshot 1 publications in unfinished games become score drafts plus audit revoke
events; completed archives remain frozen. Audio and plain session/recovery tokens
are excluded. Recovery codes are hashed, six characters, rotated/single use,
require the game password and share the five-attempt/minute join limiter. Restored
identities receive player access and revoke old sessions, never automatic host access.

## Bounded private replay

GET /api/host/review/{round_id}/audio is host-only in final review/results. No shared
PLAY/STOP or game-cache mutation. Two pending jobs maximum, one per host, default
2 MiB per upload, timeout 75 seconds, cleanup on disconnect or game/permission change.
Exact replay verifies the original SHA-256; the Bridge keeps at most 64 MiB of
short clips in its private temporary directory and may regenerate from the saved
recipe/revision. A different hash is refused, including non-deterministic Opus
muxing after restart. Changed/deleted sources never silently substitute a recording.

Full listening requires local Bridge opt-in and uses reencoded ≤30-second segments,
without loudness/fades. Offsets are finite and bounded. At most one segment Blob
remains in the browser; the full source and all video streams stay on the Bridge.
The Docker option is BRIDGE_ALLOW_FULL_REVIEW=true, default false.
Old recipes without a recorded source revision cannot request full listening.
Metadata edits acknowledge a per-round revision, including empty fields that
restore imported values; repeated rounds sharing one track are updated together.

## Sources and formats

Up to eight distinct Bridge UUIDs coexist; reconnecting the same UUID replaces only
that link. Jobs/catalogue tokens are owner-bound. A separate secret per Bridge
remains V1. SCAN_SOURCES accepts only ≤64 relative NFC subfolders inside a locally
authorized root. Symlinks/junctions in the root, parents, scanned folders or opened
file are refused. A scan traverses the root once, limits depth to 32/files to 200,000,
filters selected subfolders and preserves IDs. Overlaps never duplicate tracks.
NFC/ID collisions exclude both files. Inaccessible scans preserve the previous
catalogue with a diagnostic. Played rounds snapshot their original catalogue entry.

New files inside a current Docker mount need a rescan. New outside folders need
a read-only mount under /music and recreation of only the Bridge. The web UI cannot
extend mounts or authorize an arbitrary host filesystem path.

| Demuxer | Extensions |
|---|---|
| mp3 / flac / wav | .mp3 / .flac / .wav |
| mov | .m4a .mp4 .mov .m4v .3gp |
| ogg / aiff | .ogg .oga .opus / .aiff .aif |
| asf / aac | .wma .wmv .asf / .aac |
| matroska / avi | .mkv .mka .webm / .avi |

The extension selects a forced, whitelisted demuxer. FFmpeg/ffprobe allow file
only; MOV external references and absolute paths are disabled. First audio stream
a:0, video/subtitles/data disabled, tags/chapters/artwork removed. Playlists and
network protocols are refused. Missing audio: NO_AUDIO; invalid container/codec:
DECODE_ERROR; source under 8 seconds: TOO_SHORT; duration over 24 hours refused.
Subprocess stdout is bounded at 128 KiB, stderr retains 8 KiB; cancellation/timeout
kills and reaps the process. Production output stays AAC/M4A 128 kbit/s, 48 kHz
stereo, about 400 kB plus overhead per 25 s. Opus/WebM is optional. Tests generate
all media at runtime and never commit audio/video fixtures.

## Metadata, search and preferences

JSON version 1, ≤1 MiB/10,000 rows. Example:

```json
{"version":1,"rows":[{"bridge_id":"12345678-1234-1234-1234-123456789abc","relpath":"Music/theme.mp4","title":"Example","artist":"Example artist","featuring":null,"album":null,"year":2026}]}
```

Paths are exact POSIX NFC relative paths; optional text fields ≤256 characters,
no controls, integer year 1000..9999. Invalid document/version fails the request;
invalid/duplicate/unknown/ambiguous rows are reported independently. Non-empty
manual field > imported field > prepared title/artist tags or cleaned filename.
Removing a manual field restores fallback. Manual/imported values persist in
session snapshots and across End session; export merges values for known files.
Search does not globally probe tags: filename plus imported/manual title/artist,
Bridge/folder/extension/online/unavailable/fresh filters, pages ≤100.
Permissions: host lobby/final review/results or MC in-game. Players see metadata
only in finalized recap; clips carry no musical metadata.

Manual client audio correction ±500 ms persists locally; positive advances the
next PLAY and its STOP, without changing an ongoing source or server answer timing.
Join lock blocks new identities, preserves reconnect/recovery. FR/EN dictionaries
cover controls/errors and the language choice persists locally. Folder balancing
and live MC answers are implemented V0.2; manual track choice remains V0.3.
